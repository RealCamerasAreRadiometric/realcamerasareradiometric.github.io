Calibration

Image formation, the calibration state, the closed-form solves and the joint Levenberg–Marquardt over all blocks, on the CPU or a device.

The state

RadiometricCamera.CalibrationState — Type
CalibrationState

Everything the calibration works on: fixed scene data (board, image size, quadrature, masks, observed images ϕ) and the current parameters Θ̄ — the camera every view shares (camera, a RadiometricCameraModel), one pose per view (poses, camera → world), the material and the lighting.

RadiometricCamera.CalibrationState — Method
CalibrationState(scene, settings, camera, poses, mat, light, targets; masks = nothing, δ = 0.02,
                 external_masks = nothing, support_min = 0, region = nothing, boundary_order = 2, backend = CPU(), ϕ = nothing,
                 channel = 0, focus_fixed = Int[], mu_bounds = (0.0, 1.0), jacobian_chunk = 4,
                 sensor_models = fill(SensorModel(), length(poses)), weights = Unweighted(), quanta = fill(nothing, length(poses)),
                 sensor = NoSensorRecord(), photo_kind = Decoded(false))
CalibrationState(scene, settings, views, vig, mat, light, targets; kwargs...)

channel (0: the three channels; 1–3: that channel alone, ONE residual per measured pixel, fit_channels): a single-channel state ties the other channels' lighting coefficients and refractive indices η to channel channel's (tie_channels), which no residual reads. focus_fixed: the focus nodes the LM holds (indices; focus_block); the focus's bending smoothness rows, focus_smoothness, are set by focus_smoothness! (none at construction). mu_bounds (lo, hi) (material.mu_bounds; e.g. (0.6, 1.0): paper at most 40 % specular): the interval of the diffuse weight μ — the LM steps on the chart μ = lo + (hi − lo) σ(w) (MaterialVar), the closed-form solves clamp to it. jacobian_chunk (compute.jacobian_chunk): the dual partials per Jacobian kernel launch on a device (_jac_chunk; the CPU backend takes every slot in one chunk) — 4, not 15: local memory grows ~1.9 KB per partial, and from about 8 partials the kernel is bound by spill traffic, so 14 re-traces at 4 beat 4 re-traces at 15 by 4.3× (25,564-px view, RTX 4090, 2026-11-04); 4 also cuts the driver's local-memory reservation (bytes per thread × resident threads) ~5×. sensor and photo_kind: the photographs' ObservationModel with channel (observation_model(s), what the state's records state; by default decoded images, no sensor record: a state of synthetic renders). sensor_models: per view, the photograph's Core SensorModel (photo_set; the absent model, SensorModel(), by default: a decoded image, or a RAW photograph of a camera stated to have no characterisation). weights: the rows' weights (weighting.jl, masked_observations): Unweighted() (the default, rows as measured) or one 1/σ vector per view, each of its ϕ's length (whitened rows: the residuals and the Jacobians divided by the measured values' σ). quanta: per view, each row's RAW code step in its units (masked_observations), or nothing (a decoded image): what the data resolve (lm_abstol).

The state of the RadiometricCameraModel camera seen from poses (camera → world, one per photograph), or of views that share one geometric camera, focus surface and aperture radius, with the vignetting vig (an ArgumentError when the views do not share them). region (the run's imaged region, pixels): a tensor vignetting surface's nodes outside it are dependent (vignetting_rule, extrapolated with a zero boundary_order-th difference), its parameters the interior ones; a radial profile's nodes with less than support_min of the mean data weight are dependent the same way, continuing the supported ones with that order (RadialSupportRule). Builds the masks from the initial views (∩ external_masks) unless masks is given. Float64 targets are kept by reference (no copy). When the masked observation vectors ϕ are given (built one photo at a time from masked_vector, e.g. for full-resolution photos that do not fit in memory together), targets may be empty placeholder arrays.

Closed-form solves

RadiometricCamera.PixelParts — Type
PixelParts{J, L3, NS, F}

Per-pixel quantities for the linear solves: for every sensor sample k the aperture-integrated light responses Bd[k], Bs[k] = Σ_l w_l (Bd, Bs) (3 × J each) and the sensor weights w[k] and positions 𝐩[k], in the float type F of the render settings. Everything the solves need follows without re-rendering: I_k(a, μ) = (μ Bd[k] + (1−μ) Bs[k]) a, Md = Σ_k w_k V(𝐩_k) Bd[k], Ms likewise (_linear_rows).

source
RadiometricCamera.RadiometryParts — Type
RadiometryParts

The PixelParts of every masked pixel of every view (view order, then pixel order), the measured values ϕ (the measured channels per pixel, the same order) and their rows' weights w (weighting.jl: Unweighted(), or 1/σ per row), on the state's backend: what all_parts renders once and the closed-form solves read.

source
RadiometricCamera.all_parts — Method
all_parts(s::CalibrationState) -> RadiometryParts

The parts of every masked pixel, rendered once on the state's backend: Core's pointwise! of _PixelPartsAt (device/jacobiankernels.jl) per view, in Float64 on every backend, as the nodal heights' path (`height_float`): the closed-form solves are exact least squares on them.

RadiometricCamera.pixel_parts — Method
pixel_parts(u, v, k, view::View, mat::Material, light::EnvironmentLight, scene::Scene, settings::RenderSettings) -> PixelParts

THE PixelParts of Julia's 1-based pixel (u, v) of view k, in the settings' float type: the sensor and aperture quadratures evaluated once, so the closed-form solves of Θ_l, Θ_v and μ (solve_linear_blocks!) need no re-rendering. The sample keys are k's, so the Monte Carlo radiance matches Φ_pixel's. Device-safe: the parts kernels run it per pixel (_PixelPartsAt for the closed-form solves, _PartsAt for the LM's analytic columns).

RadiometricCamera.solve_linear_blocks! — Method
solve_linear_blocks!(s; parts = all_parts(s), light = true, vignetting = true, mu = true, sweeps = 1, reltol = 1e-4,
                     verbose = false, joint = false) -> s

Block coordinate descent over the closed-form blocks, Θ_l → Θ_v → μ per sweep (or the joint LM of solve_radiometry_gn! when joint), on parts rendered once (the geometry, material and quadrature are fixed, so every run is exact for the current state; a caller that solves twice on one state gives its parts). The blocks are coupled (the flux is bilinear in V and Θl), hence sweeps > 1 until the parts cost falls by less than reltol of its value. One sweep starts every run. `vignettingsmoothnessandgcvrecordaresolveΘv!'ssmoothnessweightandgcv_record; the joint LM has no smoothness penalty, sojointwith a nonzero weight is anArgumentError`.

RadiometricCamera.solve_radiometry_gn! — Method
solve_radiometry_gn!(s, parts; light = true, vignetting = true, mu = true, max_iter = 40, ftol = 1e-12, verbose = false)
    -> (ReturnCode.T, StopRule)

JOINT least squares over the closed-form blocks — lighting Θ_l, vignetting Θ_v (on the null space of the gauge V(𝐜) = 1, always held) and μ — by the stack's Levenberg–Marquardt, Core's chart LM (lmsolve_chart!: NLLSsolver, Levenberg's λ·I, LM_DAMPING), on the precomputed parts (no re-rendering). Its normal equations are one reduction kernel on the state's backend (_radiometry_normal_row!; the precedent of Estimation's refine_camera): only the N × N step is the host's. The flux is BILINEAR in (Θ_v, Θ_l) and affine in μ, so block coordinate descent (solve_Θ_l! → solve_Θ_v! → solve_μ!) creeps along the coupled direction: on synthetic data generated by the model itself it stopped 8 % away from the true V after 10 sweeps (FX3 fisheye, 2026-10-13); the joint step converges quadratically near the minimum. Exact Jacobian rows from the parts (_linear_rows, the parts kernel's): ∂Φ_c/∂P_q = Σ_s w_s B_q(𝐩_s) I_{s,c}, ∂Φ_c/∂a[c,j] = (μ M_d + (1−μ) M_s)[c,j], ∂Φ_c/∂μ = Σ_j a[c,j] (M_d − M_s)[c,j]. μ moves on the LM's bounded chart μ = lo + (hi − lo) σ(w) (material.mu_bounds, _μ_chart). max_iter (accepted iterations) and ftol (relative cost decrease) are Core's LM stop settings (LmStops), the stall postcondition's tolerance Core's of record ([lm] stationarity_tol). Returns the stack's termination record (Core's ReturnCode and StopRule); with nothing free, (ReturnCode.Success, ClosedForm).

source
RadiometricCamera.solve_Θ_v! — Function
solve_Θ_v!(s, parts = all_parts(s); smoothness_weight = 0.0, gcv_record = nothing) -> s

Linear least squares for the vignetting nodes (channels stacked, achromatic V), with the gauge V(𝐜) = 1 held exactly (the centre's direction absent from vignetting_basis(s), gauge_basis). The unknowns are the free directions of vignetting_basis(s): a tensor surface's nodes outside the run's imaged region are dependent (Core's BoundaryRule), not unknowns — a radial profile's below support_min of the data weight likewise (RadialSupportRule) — and a radial profile's first two nodes move together (the pole tie, V′(0) = 0).

smoothness_weight β > 0 adds the P-spline penalty λ ‖D vec(P)‖² over the free nodes (vignetting_smoothness: third differences along the lattice axes, so a field quadratic along each axis costs nothing) with λ = β Σϕ² / N / m̄ (N the free directions, m̄ the mean positive eigenvalue of DᵀD: Core's penalty_scale), so β means what the grid smoothness's does. :gcv selects β by Estimation's generalized cross-validation (gcv_curve, gcv_select) on this solve's own linear system, and pushes the selection to gcv_record (a vector; nothing: not recorded). 0 is the unpenalized solve, unchanged; without a window of 4 free nodes along either axis there is no row and the solve is the unpenalized one.

source
RadiometricCamera.solve_μ! — Function
solve_μ!(s, parts = all_parts(s)) -> s

Affine one-parameter least squares for μ: Φ = S + μ (D − S), clamped to the state's mu_bounds: one Gauss–Newton step (exact: Φ is affine in μ) of the μ-only normal equations, the reduction kernel's (radiometry_normal_equations, the additive chart).

RadiometricCamera.ApertureVar — Type
ApertureVar(r)

Θr block: the aperture radius r (metres), one variable on its log chart (the step is d ln r, NLLSsolver.update below). source
RadiometricCamera.LightingVar — Type
LightingVar(light; channel = 0)

Θl block: the 3 × J SH coefficient matrix in vec (column-major, a[c, j]) order, parametrised as a = scale · â with scale = max|a| at construction so that the optimiser sees O(1) parameters — NLLSsolver's Levenberg–Marquardt damps with λ·I, which freezes a block whose natural scale is 10⁵ (photographs in linear units against the unnormalised aperture integral). A single-channel state's block (channel = c > 0) is the measured channel's J coefficients alone: every channel's row follows it (`tiechannels`), as no residual reads the others.

source
RadiometricCamera.MaterialVar — Type
MaterialVar(mat, surface, board = nothing; height = 0, inplane = false, fixed = (), mu_bounds = (0.0, 1.0))

Θm block: the 8 nonlinear parameters (`𝛂ink, 𝛂noink, 𝛈ink, 𝛈noink; boxed bybounds), μ ∈ [0, 1] and the scene'sBoardSurface` (its printed edge, δ and σprint, is never a parameter): with height > 0 (NH = height_nparams(height)) the board warping h through its HEIGHT_NFREE free parameters (h += B y with B = height_basis(board), the board's page: Core's TargetManifold of that warping's height field — the piston and the two tilts, the poses', are never parameters; dual-number columns), with inplane = true (NI = INPLANE_NC) the in-plane print error (a, u) of BoardSurface.inplane (Core's Aspect ∘ Skew, inplane_calibration: additive, unbounded, no gauge — a rigid member and a scale are the poses'; dual-number columns). The surface shares the material block because NLLSsolver caps a cost block at ten variable dependencies, which the per-tile blocks already use.

fixed = (:material,) holds Θm (the 8 nonlinear parameters and μ) at its value although the block stays variable (HM = true, the type's last parameter: `materialfixed): its Jacobian columns are zero (no AD scatter, no analytic μ column) andupdateleaves it unchanged, while the block's warping and in-plane parameters remain free — a held material while a surface parameter rides the block (the problem builders'fixed,holdmaterial). The block size and every other column position are unchanged; the LM's λ·I damping gives the zero columns a zero step.mubounds(lo, hi): μ's chartμ = lo + (hi − lo) σ(w)(material.mubounds, the state'smu_bounds`).

valid is false for a block whose update is not finite (a NaN of a singular solve). Every residual of the block checks it (is_valid) and returns NaN, so NLLSsolver rejects the step; an accepted state is always valid.

RadiometricCamera.run_lm! — Method
run_lm!(s; maxiters = 10, maxtime = 7200.0, fixed = (), height_degree = 0, inplane = false, kwargs...) -> (; code, rule, iterations, cost)

Levenberg–Marquardt over all parameter blocks but those fixed names (of (:poses, :distortion, :focus, :aperture, :material, :vignetting, :lighting)), the surface parameters it names (:height, :inplane) and the lens block's parameters fixed names by Core's parameter names (lens_free; default none: every parameter but the skew is free; :aspect ties the focal lengths): one holding keyword (build_problem, with the model's structure height_degree and inplane). iter_callback(it, cost, camera, poses, mat, surface, light) sees the current best variables after every iteration and trace collects the per-iteration snapshots (_lm_callback, as run_lm_grid!); with a file lm_log (lm.log) a line per iteration is appended to it (_lm_log). The solve is VisualGeometryToolkitCore's one LM, lmsolve_chart! on build_problem's LmProblem under LmStops (_lm_stops: Levenberg's λ·I, LM_DAMPING) — the RELATIVE cost decrease reldcost (its ftol), the relative step test xtol_rel ([lm] xtol_rel) and the absolute step max-norm xtol (Core's of record by default); no absolute cost decrease test — the cost is in the photographs' squared units, dimensionless when the rows are whitened (a two-view 32 × 32 fixture starts at ≈ 2e-4), so an absolute threshold of 1e-12 stopped the solver with the aperture, μ and the lighting still drifting together along a flat direction. Returns Core's termination record (code, a ReturnCode: Success at a tolerance stop — Core 0.11.0, converged by definition — or at a stationary point after the rejection cap; rule, a StopRule; iterations; cost, ‖r‖² at the solution).

RadiometricCamera.refine_calibration! — Method
refine_calibration!(state; options) -> FitResult{CalibrationEstimate, CalibrationMetadata}

Refine the started radiometric state state (start_calibration or load_calibration_start) in place: the Levenberg–Marquardt over every block the options leave free (fixed), on the route the camera's type picks (lm_route: per view, in a parametric camera's own parameters; per tile for a SplineLens camera), optionally in chunks with a closed-form sweep of the lighting, the vignetting and μ between them (sweep.lm_chunk), up to lm.max_iter iterations and lm.max_time seconds. The result's estimate is the refined CalibrationEstimate; its retcode / stop_rule the LM's termination record (Core 0.11.0: a tolerance stop converged, the rejection cap judged by the stall postcondition at the final state) — (Failure, ShapeGate) when the calibrated SplineLens camera still folds over its coverage (fold_termination: no calibration; the camera is held to the coverage assertion too, calibrated_folds) or a focus node of its support runs to t̂ ≤ 0 (focus_runaway, the same validity_gate), iterations the LM iterations, rms the final relative RMS over the n measured values.

RadiometricCamera.build_problem_grid — Method
build_problem_grid(s; patch = GRID_PATCH, fixed = (), height_degree = 0,
                   smoothness = nothing, inplane = false) -> (problem::LmProblem, idx)

The per-tile LM problem over the grid-lens state, VisualGeometryToolkitCore's LmProblem (the stack's one LM, lmsolve_chart!): pose variables per view, one patch block per grid patch, the shared focus/aperture/material/vignetting/lighting blocks, and one PerTileResidual per non-empty image tile (ndeps = 10 = NLLSsolver's MAXARGS). Held (the problem's fixed variables, idx.free the free mask): the dependent patches and the blocks fixed names (of (:poses, :grid, :focus, :aperture, :material, :vignetting, :lighting), :grid the patch blocks; :material holds Θm alone while a free surface parameter rides the block, _hold_material); another name is an ArgumentError. The patch size must satisfy p ≥ 5 (the 2 × 2-window guarantee) and divide both grid dimensions — and it must stay SMALL: NLLSsolver's Hessian accumulation (updatesymA!) slices the per-cost Hessian with nvars-sized static ranges and static broadcasts, so a patch of 8 × 8 nodes (128 parameters) makes LLVM materialize fully unrolled 128 × 128 static-array code for every dep pair — a codegen memory explosion (hundreds of GB). 5 × 5 nodes (50 parameters) compiles fine; pick the grid size as multiples of 5 (default 65 × 50).

  • height_degree > 0: the material block also carries the board warping h (board_height; the HEIGHT_NFREE free nodal-height parameters, dual-number columns). A FIXED warping (nodal heights set, degree 0) is rendered by every route; the free columns need the grid route.
  • inplane: the material block also carries the in-plane print error (a, u) of the surface (Core's Aspect ∘ Skew, inplane_calibration; two dual-number columns, additive, no gauge). A fixed error (parameters set, inplane = false) is rendered by every route.
  • :height, :inplane in fixed (SURFACE_HOLDS): that surface parameter held at its start (the block carries no columns for it), as on the per-view route.

The parameters are the nodes the lens holds (Core's present_nodes; with_present, grid_present): a pixel whose window holds an absent node is an ArgumentError (no residual reads an absent node), and a patch block with no present node is no variable.

  • smoothness (a GridSmoothness, grid_smoothness; nothing = none): its rows, one cost block per patch block or pair of them.
